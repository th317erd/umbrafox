Source checkout observed at `9a9057291b5b5dd1c1362a2cc58551990532a6f6`; working files are a live integration snapshot, not a frozen or tested revision. Findings describe the pre-integration code; the implementation status below describes this worker's subsequent changes.

## Verdict

Synchronous render-thread child preparation is viable in principle, but **not by combining the current public NativeLayerRoot APIs with EGL**. It needs an explicit external-only root mode, a preparation API accepting the already-held root lock, truthful attachment success, and frame acceptance coupled to the same lock lifetime through EGL swap. Main-thread-only lifecycle/GDK work is compatible with this model provided rendering never synchronously waits for that work. This is a source-derived implementation contract, not runtime validation.

## Blocking Findings

1. **Actual same-thread lock recursion.** `RenderCompositorEGL::EndFrame` holds the MozContainer root `WaylandSurfaceLock` across `SwapBuffers`. `nsWindow::LockSurface` and `GtkCompositorWidget::GetNativeLayerRoot` refer to that same MozContainer surface. `NativeLayerRootWayland::Init`, `SetLayers`, and public `CommitToScreen` each acquire its lock internally. Calling one while the EGL root lock is held re-enters `WaylandSurface::Lock`, which calls a nonrecursive `mozilla::Mutex::Lock`. This is a concrete recursion path. Two threads waiting in mutex code alone do not establish a two-thread wait cycle.

2. **Full native initialization/shutdown own the wrong resources.** `Init` allocates the 1x1 parent buffer, changes parent scale policy, installs map/unmap/GDK/VSync handlers, and may install format feedback. `Shutdown` removes the parent's attached buffer and clears callback slots. Those are native-compositor ownership operations, not safe EGL external-child initialization. `HasBufferAttached()` can remain false until EGL's first real frame callback; it must not authorize attaching the native dummy buffer.

3. **The prototype never submits child contents.** Asynchronous main-thread `SetLayers` only updates/maps the list. It does not call `RenderLayer`. For a changed nonempty list it also requests a forced root commit and sets root commit permission false; ordinary `CommitToScreenLocked` is what restores permission after rendering. Adding that ordinary commit call would introduce a separate parent commit owner and dummy-buffer behavior, not repair the hybrid contract.

4. **Existing success state is insufficient to omit Draw.** `NativeLayerWaylandExternal::CommitFrontBufferToScreenLocked` ignores the boolean from `WaylandSurface::AttachLocked` and returns true. Attachment can fail when no buffer transaction is available. `AttachExternalImage` returns void; buffer/conversion creation can fail after it updates `mLastSurface`. `RenderLayer` can return early with stale `mIsRendered` from an earlier image. A same-pointer retry can also skip failed buffer creation. A candidate-specific success result is required, not `CommitToScreen`'s boolean, `mIsRendered` alone, or list equality. Current `GetBufferSurface` also dereferences `AsRenderDMABUFTextureHost()` without a null check; reject other host types before reaching it.

5. **Commit-skip is not currently used by EGL.** `nsWindow::LockSurface` constructs the lock with its default `aSkipCommit=false`. Synchronized child commits atomically mark the parent `mSurfaceNeedsCommit`; consequently the current root lock destructor can issue a second root commit after EGL swap. `aSkipCommit=true` suppresses only the destructor's ordinary commit: `RequestForceCommit` overrides it, and explicit `Commit()` ignores it. The hybrid path must never use either on the root.

## Smallest Safe Root Mode

Use an immutable root mode selected at construction, such as `NativeCompositor` versus `EGLExternalOnly`. Do not call ordinary `GetNativeLayerRoot()` and then retrofit its initialized root. Keep one mode-consistent owner per widget/root; reject conflicting reuse. Coordinator's final narrowed candidate is frontmost, opaque fullscreen SDR8 YUV with identity transform and no crop, supplied by one optional per-frame DrawExternal backend; existing native queues remain untouched.

In external-only mode:

- Keep the EGL root buffer, EGL window, root scale policy, existing root VSync, and parent commit permission untouched. Do not allocate/attach the native dummy buffer, call root `RemoveAttachedBufferLocked`, invoke `ConfigureScaleLocked`, install native root VSync forwarding/emulation, or disable root commit permission.
- Install **no parent callbacks**. Final agreed implementation uses a raw, non-owning external-root slot on `WaylandSurface`, protected by its existing mutex. `CreateForEGL(proof)` registers it; the root retains the parent strongly. Parent `UnmapLocked(proof)` calls `ClearForEGL(proof)` before changing mapped state or destroying the parent subsurface. `ShutdownForEGL(proof)` clears the child, unregisters the slot, and releases the strong root/child references. This replaces the initially proposed direct MozContainer hook without changing ordinary callbacks or depending on main-thread dispatch.
- No map callback is needed: the next render preparation observes the parent mapped and maps the now-unmapped child. Performing child teardown and parent unmap under one existing proof eliminates the gap in the ordinary `RunUnmapCallback()` pattern, which runs before container lock acquisition. Initialization-once plus shutdown-only, without any parent-unmap integration, is not enough to exclude stale children reappearing on remap.
- Use an explicit GL-context association for the external layer's existing fence/upload helpers. Start with supported DMABUF YUV only; do not accidentally enable SHM upload or HLG conversion as an unreviewed fallback.
- Shutdown is serialized with rendering by the root proof, unregisters the lifecycle owner, clears child ownership/reference cycles, and releases the root reference. It must not detach the EGL parent buffer or clear any parent callback slot. The dedicated child path creates no GDK resources or queued main updates, so its clear/shutdown can run on render or main under the proof. Ordinary mode's shutdown is not reusable unchanged.

This can reuse the existing root/child classes and buffer transactions. It does not need WR native-surface IDs, a native queue, tile-cache IDs, or a second compositor hierarchy.

## Per-Frame Transaction

Proposed narrow interface: a mode-specific `PrepareExternalFrameLocked(rootProof, candidate-or-none)` with an explicit accepted/rejected result. The name is illustrative; it is not an existing API.

1. Finish EGL BeginFrame resize/MakeCurrent work first. When final-render selection reaches the candidate decision, acquire the actual widget root lock with skip-commit. Validate mapped state, external-mode lifecycle generation, dimensions/scale, and EGL availability under that proof. Do not call a lock-taking root getter or perform synchronous main-thread dispatch here.
2. Keep this exact root proof alive until the corresponding `SwapBuffers` completes. `EndFrame` must reuse it instead of acquiring the root a second time. Acquiring/releasing a lock just for candidate preparation leaves a lifecycle/parent-commit gap before swap. Audit early-return, hidden-window, pause, teardown and failed-frame paths so no staged child is accidentally published or a root lock retained.
3. Accept only the final-render, Draw-path, frontmost fully opaque, full-target SDR8 YUV candidate with identity transform and no crop, as established by the parent's selector. Full target means the actual EGL root coordinate extent, not just a video viewport. Hold a strong texture-host reference for the accepted frame and subsequent buffer lifetime. No native compositor IDs are needed, and no existing native queue changes are required.
4. Under the root proof, configure/reuse one opaque external child with `AttachExternalImage`, position, rectilinear transform, clip and sampling metadata. Map it using `Map(rootProof)` if needed. `Map` returning false while main-thread unmap cleanup is pending means reject this frame, not wait. Preserve synchronized child mode.
5. Prepare/render the child on the render thread. The child acquires its own surface lock; child commit calls `mParent->ForceCommit()`, which is only an atomic flag store, not parent mutex acquisition. Pass the root's current scale and coordinate-scale state without changing parent scale policy. Refresh or reject changed color metadata: `SetColorProperties` currently runs on Map, not every subsequent image attachment.
6. Authorize Draw omission only after this candidate's real buffer import/transaction attachment has succeeded and geometry is visible/mapped. Propagate `AttachLocked` failure; fix failed-import retry and stale rendered-state handling for this result. If reusing the same BufferSurface pointer, establish that it still denotes the intended content/fence generation, rather than treating pointer identity as a universal new-frame proof. Preserve the existing producer-fence wait and Wayland transaction/release ownership; do not add fence deletion or replace waits with assumed readiness.
7. EGL performs the parent buffer attach/commit through swap. Do not call native root `CommitToScreen`, `SetCommitStateLocked(false)`, root `Commit()`, or `RequestForceCommit()`. Child commits remain necessary: skip-commit belongs to the EGL parent lock, not the child locks.
8. Account for the parent's pending-commit bookkeeping. A successful EGL swap does not currently clear `WaylandSurface::mSurfaceNeedsCommit`. Add a proof-checked notification that the external owner performed the root commit, or an equivalent mode-specific mechanism, before releasing the proof. Do not clear pending state on failure or blindly discard concurrent child-only updates. In the narrow single-child mode, disable native child VSync routing and serialize all mutating child operations under the same root proof, including main-thread updates, to make this accounting well-defined. Preserve baseline EGL/root VSync callbacks and GDK commits; do not globally disable Wayland commits.

Do not defer only SetLayers to main or defer the whole child render until after swap. Both are too late to justify current-frame Draw omission. If the parent WR/FFI integration cannot preserve a synchronous accept/reject decision and root-lock lifetime, this design is not yet safe to enable.

## Fallback And Main-Thread Work

For a rejected/no-candidate frame, remove any previous external image from the presented frame while drawing the normal fallback. A reusable mapped child can use `SetClipRect(Some(emptyRect))` followed by `RenderLayer(scale)`: `UpdateLayerPlacementLocked` makes it invisible and calls `RemoveAttachedBufferLocked`; the child-lock destructor commits the null attachment in synchronized mode, for the upcoming EGL parent swap. Restoring a visible clip marks placement/visibility dirty and permits reattachment. This avoids relying on `SetLayers(empty)` or immediate subsurface destruction for atomic per-frame removal. Keep full damage on enable/disable transitions as required by the renderer's buffer-age/damage contract.

Perform actual `Unmap`/`MainThreadUnmap` when the widget/root unmaps or shuts down, not as the only per-frame fallback mechanism. Child `UnmapLocked` destroys its subsurface and releases transaction references; do not claim that destruction is equivalent to a synchronized null-buffer update. A failed/aborted frame after staging needs an explicit cancel/restore policy before the root proof is released; otherwise later baseline root commits can publish that staged child against the wrong root frame.

`MainThreadMap`/`MainThreadUnmap` exist for GDK opaque-region registration/cleanup. Existing code explicitly treats delayed main-thread updates as noncritical for rendering. Keep asynchronous dispatch, strong references, and root-before-child lock order. In external-only mode these updates must not add native root commits. Root lifecycle and metadata ownership need serialization, not a render-thread wait for GTK completion.

The normal child VSync route is unsuitable: `NativeLayerRootWayland::VSyncCallbackHandler` acquires the root and commits pending synchronized work, then routes child pacing into root VSync. Omit that route in external-only child Map; retain required visibility/buffer-release lifecycle. This does not prove the old VSync path deadlocks: `WaylandSurface::VSyncCallbackHandler` releases its own surface lock before invoking the registered callback. The concrete bad path is same-root public-API re-entry, not a proven child-to-parent mutex cycle.

## Implemented API

All methods below use the caller's existing root proof; none reacquires the root mutex:

- `CreateForEGL(WaylandSurfaceLock&)`: creates an external-only root and one reusable opaque child, registers the parent's non-owning slot, and does not call normal Init or alter parent logging identity. Caller sets the existing GL context with `SetGLContext` before preparing candidates.
- `PrepareForEGL(WaylandSurfaceLock&, RenderTextureHost*, const IntSize&)`: returns true only after successful current-frame child attachment. Null input or rejection returns false and stages a synchronized null attachment. This is not the same as teardown. Keep the root proof through EGL swap, with skip-commit selected by the caller.
- `ClearForEGL(WaylandSurfaceLock&)`: destroys the child subsurface, releases child-owned buffer/host references, and resets state while preserving the reusable child object. The parent invokes it before parent unmap and on frame cancellation. Existing Wayland transaction/release lifetimes remain responsible for compositor-held buffers.
- `ShutdownForEGL(WaylandSurfaceLock&)`: single-shot clear, unregister, break root/child references, release the parent reference. Do not use ordinary `Shutdown()` for an external-only root.

The dedicated child path uses `MapLocked`, immediate `SetOpaqueForEGLLocked`, map-time color representation, direct full-source/full-destination viewport setup, full child damage, existing `FenceWait`, and the real `AttachLocked` result. It does not use ordinary NativeLayer `Map`, `RenderLayer`, SetLayers, root CommitToScreen, GDK opaque registration, native VSync forwarding, or per-frame dispatch. Native/Layer-path implementations are unchanged, apart from mode guards against using ordinary Init/Shutdown on the external-only root.

The helper gates source dimensions equal to the supplied root-frame dimensions, root scale exactly one, an existing EGL window/GL context, DMABUF YUV, NV12/YUV420, actual surface depth eight, BT709 limited range, explicit BT709 transfer, and no HDR transfer. It additionally requires an advertised color-representation manager and nonzero BT709-limited support. A mapped child's changed chroma-location metadata is rejected until clear/remap, rather than mutating a single-instance color-representation object. Missing color protocol support explicitly means ordinary Draw fallback; it may leave Pi unsupported, and is not a performance claim.

Same-buffer reuse still waits on the producer fence and attempts attachment on every frame. Failed imports/attachments discard the failed cached front buffer so a later attempt can retry. Failed subsurface creation retires the unmapped child, because ordinary MapLocked leaves partial parent state on that failure path; normal frames reuse the child. The path does not delete fences. Only the child is attached/detached; parent buffers, callbacks, scale, and commit permission remain untouched.

Parent integration must call `NotifyEGLSwapLocked` only after successful swap, maintain skip-commit for the retained parent proof, and clear staged children on cancellation. Cancellation can expose the prior EGL image, which may itself have omitted the video; schedule a full ordinary fallback redraw rather than claiming cancellation restores the last complete video frame. The selector must also exclude capture/readback cases that need video pixels in the EGL target unless its capture path explicitly composites the external child.
