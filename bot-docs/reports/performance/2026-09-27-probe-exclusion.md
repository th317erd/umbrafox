## Scope and provenance

The patch retains the experimental diagnostic source while adding opt-in
`--enable-umbra-perf-probes`, `MOZ_UMBRA_PERF_PROBES`, and Cargo forwarding through
`gkrust-shared/umbra_perf_probes`, bindings and WebRender `umbra-perf-probes`.
Wrench forwards the feature separately. All source defaults remain OFF.

Six build-wiring files and ten native Rust files gate custom marker state,
helpers, accessors, imports and entire argument expressions. The custom
eligibility predicate requires a marker sink as well as a profiled thread.
Sampling cleanup covers observed eligibility loss, disabling and shutdown.
Rendering, shaders, opacity eligibility/defaults, GL calls and upstream counters
are unchanged by this delta. No public browser interface is added.

The checkout already contains uncommitted experimental renderer work. The
implementation-only delta, reconstructed pre-edit hashes and protected-file

`~/.cache/codex/umbra-perf-20260927/probe-gate/`

`implementation.patch`, `after.sha256` and `checkpoint.md`. The earlier native
base is `44f0ad5f3277a51138cba9dd11aeb3a61d5a31c9`; the tools/docs-only commit
`892431809a4c` advanced HEAD without absorbing that native work. A commit ID alone

## Reproducible OFF checks

Run from the repository root. These are compilation commands, not read-only
inspection: dependency build scripts run and profiler bindings are generated
inside the scratch target. They do not launch a browser or change its install.
Record inherited Cargo/Rust overrides and source/input hashes first.

```bash
R=/home/wyatt/Projects/umbrafox-workspace/umbrafox
S=/home/wyatt/.cache/codex/umbra-perf-20260927/probe-gate
C="$R/obj-x86_64-pc-linux-gnu/.cargo/config.toml"
B="$R/obj-x86_64-pc-linux-gnu/build/rust/mozbuild/buildconfig.rs"
env BUILDCONFIG_RS="$B" CARGO_NET_OFFLINE=true timeout --signal=TERM 300s \
  cargo --config "$C" check --offline --locked -j 2 -vv \
  -p webrender --lib --target-dir "$S/gecko-wr-off" \
  > "$S/gecko-wr-off-configured.log" 2>&1
env BUILDCONFIG_RS="$B" CARGO_NET_OFFLINE=true \
  LIBCLANG_PATH=/home/wyatt/.mozbuild/clang/lib \
  CLANG_PATH=/home/wyatt/.mozbuild/clang/bin/clang++ \
  LD_LIBRARY_PATH=/home/wyatt/.mozbuild/clang/lib \
  timeout --signal=TERM 300s cargo --config "$C" check --offline --locked \
  -j 2 -vv -p webrender_bindings --lib --target-dir "$S/gecko-wr-off" \
  > "$S/gecko-bindings-off.log" 2>&1
```

Reuse of the OFF scratch target avoids recompiling unchanged dependencies. Logs
retain the exact rustc cfg, source paths and generated-output paths. Do not
overwrite these completed logs when repeating the checks.

## Preserved setup failures and remaining gates

Standalone offline WR resolution first lacked its exact gl-rs git revision;
using Gecko's vendor configuration then encountered Wrench's optional
`osmesa-src` git revision. Both failed before compiling WR. The first root
attempt lacked `BUILDCONFIG_RS`; the configured retry above succeeded. These are
preserved setup failures, not suppressed source errors.

Root `-p webrender --features webrender/umbra-perf-probes` is rejected because WR
is an excluded workspace dependency. Supplying the shared feature with the same
selected package also fails. Whole-workspace metadata resolves the intended
three-edge feature propagation, but that does not validate either selected
compiler command or package feature unification.

A subsequent selected graph using `-p gkrust-shared --features umbra_perf_probes`
resolved successfully (`root-shared-on.features`). This member is the direct
consumer of bindings, but includes 96 required unconditional/Linux normal
dependencies. A separately reviewed, two-job, 300-second offline/locked check
used the same generated/clang inputs and a new `gecko-shared-on` scratch target.
It stopped with exit 101 in the `nss_sys` build script: `NoNssDir`, with an
`NSS_DIR` input named by that script. Neither WR nor bindings ON compilation was
reached. Preserve `gecko-shared-on.log`; no guessed environment retry, export or
dependency change was made. This is a broader-check prerequisite gap, not a
diagnostic source verdict. No ON compile success is claimed. Do not spoof a cfg
or treat the pure fixture as a substitute.

Independent source review then identified the omitted normal `rust.mk` export
`MOZ_TOPOBJDIR`. Its presence selects `mozbuild::link_nss`; actual paths come
from the existing compiled buildconfig, not a new standalone NSS installation.
One separately reviewed continuation added only
`MOZ_TOPOBJDIR=/home/wyatt/Projects/umbrafox-workspace/umbrafox/obj-x86_64-pc-linux-gnu`
to the prior process environment, preserving the same offline/locked/two-job/

Still required: real ON crate checks, configure integration, generated ABI and
