# Backward Seeking With Failure Evidence

## Decision

Previous wave made progress: one private full-feature driver forward capture
completed and showed a large descriptive RDD CPU reduction; backward capture
HNGm4l stopped on the unchanged artifact scan's three-ENOENT limit. All owned
processes are gone. The 80-file prior seal remains immutable.

One fresh isolated laptop backward capture after a narrow failure-evidence
repair, not an unchanged retry. No desktop/Pi/system install, native build,
product/default/public-interface change, profiler, extra browser RPC or agents.
Same browser, private driver, 1080p ordinary menu and progress-bar input, with
20-second baseline and 130 seconds after seeked. No cap or timeout increase.

## Error Contract

The current resource monitor poisons its signal with the original error but
calls the capture abort callback with only reason.message. Capture-level catch
therefore cannot recover a nested filesystem cause. Use its existing injected
sample seam to observe rejection before this conversion, then rethrow the SAME
error. Do not alter the shared monitor or sampler, and do not retry on failure.

New scratch helper retains one bounded structured record only: recognized
error kind, cause code, syscall, owned root/profile/app-data/local-data/temp
category, a finite known storage category and SHA256 of an owned relative path.
No message, stack, absolute path, filename, file contents, arbitrary properties
or outside-root path hash. Own data descriptors only; getters are not invoked.
Unexpected descriptors/values become unknown. No failure record is written if
the original monitor signal already aborted. No reads/writes after delayed
rejection except the existing caller's handled rejection path. Preserve the
first record; never replace the primary error with diagnostic failure.

Generate new copies of the three previously sealed runtime adapters, retaining
exact inverse-delta tests and AST import relocation. Only capture gains the
sample wrapper; YouTube/recovery imports point to the new copy. Record observer
change: an additional async wrapper per passive sample, not zero-cost proof.

## Gates

Failing tests for original message-only forwarding, private path/cause handling,
late abort, repeated failure, success passthrough, getters, malformed values and
exact generation/source drift. Run existing seeking and driver tests. Reverify
prior seal and new closure before transport; exclusive fresh laptop directory,
host no-browser/compiler preflight, memory/disk admission and fixed caps.

After terminal capture, verify cleanup/all recorded PIDs absent, package/closure
hashes unchanged, raw export bounds/hashes and original seek/quality validators.
If successful, compare only to the matching earlier software backward capture,
with process/window/time joins and descriptive N=1 limits. If stopped, preserve
failure evidence and stop this wave; no implicit repeat or safety bypass.
