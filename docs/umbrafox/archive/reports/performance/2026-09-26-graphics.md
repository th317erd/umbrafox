## Producer-to-consumer map

1. **Content/video producer:** `CanvasRenderingContext2D::DrawImage` selects remote
   video/descriptor handling. The local `MaybeGetScaledSourceSurfaceForRemoteVideo`
   checks remote DMABUF type, full-source draw, identity transform, linear filter,
   integral dimensions, no rotation; callers exclude filters/shadows. Excluded or
   failed sized requests retain legacy fallback. There is no new structured
   decision/latency marker in the inspected change.
2. **Readback producer/consumer:** `GPUVideoImage::GetAsSourceSurface(size)` ->
   `RemoteMediaManagerChild::Readback` -> synchronous `PRemoteMediaManager.Readback`
   -> `RemoteMediaManagerParent::RecvReadback` ->
   `DMABUFSurfaceImage::BuildSurfaceDescriptorBufferForSize` ->
   `DMABufSurfaceYUV::BuildSurfaceDescriptorBufferForSize`. The parent allocates
   shmem, returns null on sized failure, and the canvas caller takes fallback.
   Child `SyncRunnable::DispatchToThread` adds a thread handoff before sync IPC.
3. **GL/readback boundary:** `DMABufSurface::ReadIntoBuffer` imports textures when
   absent, creates a texture/FBO, `fTexImage2D`, `GLBlitHelper::Blit`, then
   `ReadPixelsIntoBuffer`. Sized blit retains visible-region crop matrices but
   omits native texSize clipping. At 320x180 RGBA the logical output is 230,400
   bytes rather than 8,294,400 for 1080p: 36x fewer logical output bytes, **not**
   measured bus traffic or a 36x speedup. Shared snapshot context locking,
   allocation, conversion, GL submission, completion and IPC are not separated.
4. **Canvas/update/upload boundary:** historical live-copy stacks establish
   content Skia drawing/shared-buffer paths; cached putImageData stacks establish
   CanvasRenderer `DrawTargetWebgl` upload/presentation paths. Backing is not
   invariant and must be recorded. Texture/client updates feed the async image
   pipeline; WR's texture-cache upload counters do not cover every canvas upload.
5. **WR producer/consumer:** `AsyncImagePipelineManager::ApplyAsyncImageForPipeline`
   updates keys/epochs, holds external images and sets `PREFER_COMPOSITOR_SURFACE`.
   Local `SceneBuilder::fold_single_image_opacity` optionally carries private
   instance opacity. Tile dependency/promotion code -> `ExternalSurfaceDependency`
   -> resolved RGB modulation -> both composite consumers; fallback quads multiply
   alpha and preserve opacity invalidation dependencies. Debug RGB decisions,
   target submissions and aggregate promotion counters observe this layer.
6. **Driver/fence:** WR GL commands -> Mesa/V3D queues and dependencies. Local
   sampling operands only join CPU-side inputs/submissions; actual sampler weights,
   intermediate texels and GPU completion are explicitly unknown. Historical
   scheduler/fence traces identify queueing clients, not individual WR targets.
7. **Compositor/present:** `RenderThread::UpdateAndRender` -> `RendererOGL` ->
   `RenderCompositorEGL::EndFrame` damage handling, Wayland surface lock, SwapBuffers
   -> Cage -> display. Upstream EGL has no `WaitForGPU` override: base returns true;
   base `GetLastCompletedFrameId` returns previous frame ID. Consequently the
   generic `wr.gpu_wait_time` call and frame IDs are not Pi fence/scanout proof.
   Actual lock, swap, driver wait and presentation completion need separate joins.

Ambiguity, unsupported native compositor, missing metadata, untraced blits/clears

**Disabled overhead, observed source:** formatting, source scans, generation lookup
and candidate atomic IDs are behind active gates. But sampling module/state and
calls are unconditional in the inspected Rust configuration; helper calls test an
Option even without a trace; per-update candidate state is reset. The experimental
shader handle is constructed unconditionally in `CompositorShaders::new` (this is
not proof of eager driver compilation). Added image-opacity/modulation fields and
eligibility branches also exist with the optimization OFF. Release symbol/code-size
impact and cycle costs were not measured. No current dedicated release exclusion
around the costly sampling feature was found in its module/hooks/state definitions.

**Enabled overhead:** bounded is not free. String formatting/allocation, metadata
lookups, source scans, copying operand bits, marker writes, atomics and target clocks
can perturb latency. Historic 2x2 feature/logging controls establish same-mode
pixels and marker gating, not timing neutrality. Logging also includes existing
warning behavior. Do not enable it during acceptance timing or equate it with the
smallest future aggregate-counter mode.

**Durability contract recommended:** leave probes and tests in tree, with a distinct
opt-in diagnostic build feature that excludes costly code, state, imports, call-site
argument evaluation and dependencies from production release. Compile-time gating
must not change the rendering branch itself. Keep low-cost upstream counters;
split summary markers from the operand recorder. Validate feature-present/OFF,
feature-present/ON and production-feature-absent builds, including diagnostic
runtime toggles after an incomplete or completed trace. Do not use the existing
one-shot trace as an unlimited general recorder without redesigning its lifecycle.

No new WebIDL, JS globals, CSS interfaces, request headers, page console messages
or page-accessible performance entries were added by the inspected marker changes.
Keep IDs internal and process-local; no page text, URLs or pixels in aggregate
payloads. This structural finding is not a timing-indistinguishability proof.
Private browsing/container/RFP and exception-order parity remain required gates.

## Prioritized opportunity catalog

### G1. Release-excluded durable diagnostics and overhead controls (P0 prerequisite)

- **Observed:** runtime gating and bounds exist, dedicated production exclusion
  does not; control pixels pass historically, overhead is unquantified. High
  source confidence. References: renderer `sampling.rs`, `mod.rs`, `init.rs`,
  `shade.rs`; `S/docs/umbrafox/archive/reports/single-image-opacity-prototype.md`, exact-sentinel
  continuation; `exports/wr-profiler-20260925/README.md`.
- **Producer -> consumer:** WR promotion/targets/operand hooks -> Gecko profiler
  -> strict parser and summary analysis. Retain current names/schema; add an
  internal probe-build identity and bounded summary health/dropped-record count.
- **Hypothesis/workload:** diagnostic overhead could obscure residual 2.5-3.5%
  cached drops; test static, cached and live-copy controls in both feature states.
- **Gate / next falsification:** release binary lacks operand probe code/state;
  logging-OFF does not scan/allocate; logging-ON has bounded allocations and no
  pixel/semantic change. Compare to no-probe baseline with predeclared uncertainty
  margins. A clear OFF regression falsifies the cheap-disabled-path assumption.

### G2. Opacity intermediate removal (P1 measured opportunity, parity-blocked)

- **Observed:** cached OFF/ON reversal and disappearance of picture-target
  submissions; all four hardware pixel oracles fail and every ON timing gate fails.
  High numeric confidence; diagnostic-path confidence relies on retained report.
- **Producer -> consumer:** async RGB canvas -> opacity scene fold -> image
  dependencies/modulation -> fallback or promoted RGB -> composite shader. Observe
  `WR RGB promotion`, `WR picture target`, `WR promotion counters`, experimental
  shader selection, and `NumPictureCacheInvalidated`/`NumDrawCalls` as available.
  The former legacy tile name counts rendered targets, not uniquely invalidated
  page elements (`H/browser-raster-profile-review-20260925.md`).
- **Hypothesis/workload:** avoiding repeated full-HD intermediate work explains
  part of the observed benefit; exact per-job attribution is not proven. Preserve
  all four frozen cases and cached/plain brackets, including alpha/clip exclusions.
- **Gate / next falsification:** exact framebuffer and readback parity, no timing
  API difference beyond Firefox-compatible behavior, actual intended path, and all
  timing repeats within original gate. A parity-preserving variant that restores
  target count or loses benefit falsifies the proposed useful specialization.
  No tolerance relaxation, broad flattening, or default enabling is justified.

### G3. Residual live-copy readback and allocation (P1 measured residual)

- **Observed:** ON live copy still drops 8.562% versus cached 2.522% in ON1;
  workloads/backings differ, so subtracting them does not yield readback cost.
  Historical `H/browser-profiler-review-20260925.md` has 124 Readback runnables
  on one MediaSupervisor thread (mean 23.04 ms, max 77.22); 376 of 433 sampled
  ReadIntoBuffer stacks map to ReadPixelsIntoBuffer. This is historical, partial
  thread coverage, not fresh unprofiled timing. High source, medium attribution.
- **Producer -> consumer:** DrawImage -> child handoff/sync IPC -> RDD shmem,
  GL blit/readpixels -> content SourceSurface -> canvas upload/presentation.
  Proposed internal spans: `CanvasVideoReadbackDecision`, `RemoteVideoReadback`,
  `DMABufReadbackAllocate`, `DMABufReadbackBlit`, `DMABufReadPixels`, carrying a
  scoped request ID, coded/visible/requested dimensions, result/fallback reason,
  byte counts and existing backing type. These names are proposals, not present.
- **Hypothesis/workload:** synchronization or repeated allocation remains costly;
  neither buffer pooling nor zero-copy import is proven necessary. Compare cached
  versus live updates at recorded achieved cadence, before/after provider warm-up,
  hidden/visible and small/fullscreen destinations.
- **Gate / next falsification:** measure each stage and fallback count; only pursue
  pooling if allocation has meaningful measured cost, or import if readback dominates
  and ownership/fences/color/crop/context-loss parity can be preserved. Sized guard
  rejects only when both dimensions are >= source; mixed-axis upscale/downscale is
  admitted by source and deserves a dedicated parity case, not the blanket label
  "smaller in both axes". Also test unsupported, failed, cropped, rotated, filtered,
  nearest, fractional and demoted-provider paths. No causal conclusion from code.

### G4. Upload and canvas backing transitions (P2 attribution gap)

- **Observed:** earlier live-copy WR upload payloads were 230,400 bytes (133
  uploads mean 2.41 ms/p95 10.71; small-copy 185 mean 1.99/p95 6.66). Earlier
  cached run had no Renderer upload markers yet CanvasRenderer UploadSurface/
  FlushFromSkia/PresentTexture samples. References: both profiler reviews in `H`.
  Medium confidence, historical profiles, distinct windows and backing paths.
- **Producer -> consumer:** CPU raster/recording buffer -> CanvasRenderer or shared
  TextureClient -> external-image resolve / WR texture cache -> driver. Use the
  existing upload counters above, and a new bounded `CanvasUploadSummary` with
  backing transitions, calls/bytes, copy-versus-import and destination dimensions.
- **Hypothesis/workload:** copies/provider transitions may explain part of residual
  cost; absence of WR uploads is not absence of upload. Use identical cached/live
  sources and record actual backing over warm-up, not an acceleration pref/debug
  overlay. CPU upload time and deferred GPU cost need separate totals.
- **Gate / next falsification:** complete per-producer accounting, no default
  backend forcing or quality reduction; test context loss and resource recycling.
  If upload time/bytes remain small and downstream waits dominate, deprioritize
  another upload optimization instead of generalizing from sample names.

### G5. Renderer queue/backpressure versus lock/swap/presentation (P2)

- **Observed:** `H/browser-kernel-attribution-review-20260925.md` reports complete
  Renderer RCL submit-to-IRQ time 3664.872 -> 5497.746 ms, and median queue-to-run
  8.745 -> 76.482 ms, plain versus cached. CanvasRenderer RCL cached work was
  54.318 ms over 210 complete jobs; Cage RCL fell 3016.208 -> 1593.664 ms. There
  were 6/104 incomplete plain/cached jobs excluded. This supports Renderer backlog
  as a historical direction, not individual-pass attribution or new Pi ON data.
- **Producer -> consumer:** renderer GL submissions -> V3D fence/scheduler jobs ->
  EGL swap/Wayland buffers -> Cage/display. Existing `Composite #...` spans and
  `wr.gpu_wait_time` are insufficient; proposed `WRSurfaceLock` and `WREGLSwap`
  spans, submission/window identity, damage area, buffer age and swap path should
  correlate to OS-owned fence-context/sequence and existing presentation events.
- **Hypothesis/workload:** reduced intermediate work relieves renderer backlog;
  residual delay might instead be buffer availability or presentation. Test the
  same plain/static/cached/live window matrix; do not sum overlapping engines,
  queued waits as utilization, or align historical profiles with later traces.
- **Gate / next falsification:** attribution must survive complete-job/clock checks;
  acquire no extra fences/glFinish/timer-query stalls merely for timing. If waits
  belong to another producer or occur after GPU completion, revise the mechanism.
  Do not replace Cage or bypass synchronization based on SwapBuffers occupancy.

   this as acceptance. The falsifying question is whether residual live-copy stalls
